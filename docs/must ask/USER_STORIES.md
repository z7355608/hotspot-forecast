# USER_STORIES.md

> 项目「爆款猫」核心用户故事 + 主链路验收 + 失败兜底。
> 真值同源:[docs/PRD-v1.md](../PRD-v1.md) §3 / [docs/business/产品定位.md](../business/产品定位.md) §谁是用户。
>
> v1.0 唯一聚焦的用户:**抖音 / 小红书的中腰部自媒体创作者**(粉丝 1k–50k),
> 痛点是"不知道现在该拍什么",不是"不会拍"。

---

## 用户故事模板

### 用户角色:[name]
- **用户任务**:[一句话:用户为什么打开本产品]
- **使用场景**:[在什么情境下打开 / 上次打开后多久]
- **前置条件**:[完成了哪些前置步骤——注册 / 绑定 / 充值 / 输入]
- **操作过程**:[用户在产品里做的具体动作,1-2-3 列出]
- **成功结果**:[用户期望拿到的产物 / 决策 / 行动]
- **失败结果**:[出错时用户会看到 / 体感如何]
- **验收标准**:[QA / 产品评审时能 yes/no 判断的可观测标准]

## 核心用户角色

### 用户角色 A:腰部以下中度活跃创作者(v1.0 主用户)

> 1k–50k 粉,主战场抖音 / 小红书 / 快手中的 1 个,副战场 1 个,每周更 2–7 条。

| 维度 | 描述 |
|------|------|
| **用户任务** | 30 秒内决定"今天 / 这周拍什么",省掉每天刷热搜决策的 30–60 分钟 |
| **使用场景** | 早上 9–11 点 / 晚上 9–11 点,内容计划日;打开"爆款选题推荐"页 |
| **前置条件** | 已在 manus.space 注册并登录;新用户已收到 60 积分赠送(够 1–2 次完整预测) |
| **操作过程** | ① 进入"爆款选题推荐"页;② 输入框填入赛道关键词 / 对标视频链接 / 账号链接(三选一,1 次点击,见 [PRD-v1.md](../PRD-v1.md) §3);③ 点击"开始预测";④ SSE 流式等 30 秒;⑤ 看 3 张选题卡片(轮播);⑥ 选定 1 张 → 点击"生成开拍脚本"或"拆解对标样本" |
| **成功结果** | 30 秒内得到 3 张选题卡(标题 + 切入角度 + 爆发指数 + 对标样本 + 核心标签);选定一张后一键跳到脚本编辑器,上下文已预填(见 [PRD-v1.md](../PRD-v1.md) M4) |
| **失败结果** | 30 秒未拿到结果时:见"主链路失败兜底"。常见 case:① TikHub 余额不足("余额不足"提示);② 健身减脂等赛道触发 502(P0-1,目前可复现);③ 登录态卡(P0-2);④ 反向代理未通(P0-3);⑤ 页面反复刷新(P0-4) |
| **验收标准** | M1:进站可用率 ≥ 95%;M2:稳定输出 ≥ 3 张卡片字段齐全;M3:相关性 ≥ 80%(50 条人工抽样);M4:点击"生成开拍脚本"必须跳到编辑器并预填该选题上下文;选题点击转化 ≥ 30%;NPS(20 人) ≥ 30 |

---

### 用户角色 B:MCN 实习生 / 助理(次级用户)

> 帮 1–3 个创作者整理选题的中间角色;典型行为:替别人查 / 收藏 / 整理。

| 维度 | 描述 |
|------|------|
| **用户任务** | 一次性给所负责的几个创作者拉一遍选题,整理成清单交差 |
| **使用场景** | 每天早会前 30 分钟,批量跑几个赛道 |
| **前置条件** | 同角色 A;v1.0 期间**没有团队协作 / 共享 workspace 功能**(明确不做,见 [PRD-v1.md](../PRD-v1.md)) |
| **操作过程** | ① 一个赛道一个赛道单独跑;② 把 3 张选题卡截图 / 复制文案给创作者本人 |
| **成功结果** | 同 A;但是为多个赛道跑多次预测 |
| **失败结果** | 同 A |
| **验收标准** | 同 A;**无单独验收项**(v1.0 不给 MCN 独立功能,他们只是把产品**当个人工具**用) |

> 取舍说明:[PRD-v1.md](../PRD-v1.md) §2 明确"不服务 MCN 投放运营"——
> 这里的"MCN 实习生"是指"把产品当个人工具用的助理",**不是产品级 MCN 客户**。

---

### 用户角色 C:自媒体小工作室 2–5 人(次级用户)

> 团队协作做选题。和角色 B 类似:v1.0 当产品当**个人工具**用,无团队功能。

| 维度 | 描述 |
|------|------|
| **用户任务** | 团队成员各自跑预测,在群里(微信 / 飞书)同步结果 |
| **使用场景** | 周一上午选题会议前 |
| **前置条件** | 同角色 A;**没有团队 workspace / 共享历史功能** |
| **操作过程** | 同角色 A,各自的账号各自跑 |
| **成功结果** | 同 A |
| **失败结果** | 同 A |
| **验收标准** | 同 A;无团队级验收项 |

### 不是用户(明确剔除)

(取自 [docs/PRD-v1.md](../PRD-v1.md) §2 / [docs/business/产品定位.md](../business/产品定位.md))

| 不是谁 | 为什么 | 产品行为 |
|-------|-------|--------|
| **MCN 投放运营** | 要的是规模化数据看板,不是单选题 | 不开数据看板能力;价格定位也不卡他们的预算 |
| **知识博主写长文** | 爆款逻辑不一样 | 主流程对长文场景不优化 |
| **品牌投放方** | 要的是种草数据 | 不开品牌投放分析 |
| **100 万粉以上大号** | 已有专业团队 + 自有数据 | 算法在大号场景下"契合分"压低,不强推 |
| **真·新人(0 粉)** | 没有 TA 自己的"前 25%"作参照 | 北极星指标无法计算;产品不报错但对他们价值低 |
| **严肃媒体** | 选题逻辑是"事件 + 责任",不是爆款数据 | 不主动覆盖 |

## 主链路验收

### 1. 用户能否完成核心动作(M1–M4)

(取自 [PRD-v1.md](../PRD-v1.md) §3 / §4 / §6)

| 项 | 验收 |
|---|------|
| 用户能从落地页**完成注册**并进入"爆款选题推荐"页 | 进站可用率 ≥ 95% |
| 用户能在 1 个输入框、≤ 1 次点击内**提交一次预测**(关键词 / 链接 / 账号) | 输入约束见 [PRD-v1.md](../PRD-v1.md) §3 |
| 用户能在 **30 秒内**(P95)看到 **≥ 3 张选题卡片** | M2 + 预测时长 P95 ≤ 30 秒 |
| 选题卡字段齐全:标题 / 切入角度 / 爆发指数 / 对标样本 / 核心标签 | 字段冻结,见 [client/src/app/store/prediction-types.ts:282–305](../../client/src/app/store/prediction-types.ts) |
| 用户选定一张后能**一键生成开拍脚本** | M4:跳到脚本编辑器并**预填**该选题上下文(标题 / 角度 / 对标 / 标签) |
| 用户能**一键拆解对标样本** | 走旁路 `viralBreakdown` / `viralBreakdownDirect`,见 [server/routers/copywriting.ts](../../server/routers/copywriting.ts) |

### 2. 用户能否理解结果

| 项 | 验收 |
|---|------|
| 「**爆发指数**」用户能直接看懂(0–100,数值越高越值得拍) | 取代"机会分"等内部黑话(见 [DOMAIN_RULES.md](DOMAIN_RULES.md) §1) |
| 「**对标样本**」是真实采集的内容,用户可以点过去验 | 字段含 `referenceTitle` / `referenceId` / `referenceAuthor` |
| 「**切入角度**」一句话讲清楚"为什么这么拍" | 由 trend / topic 合并 LLM 调用直接输出 |
| 「**结论**」(`conclusion` + `conclusionSub`)给出"今天就拍 / 优先级最高"的产品语言 | 字段冻结 |
| 「**怎么拍**」(`howToShoot`)给出具体拍摄方法 | 字段冻结 |
| 「**为什么现在**」(`whyNow`)给出时机判断理由 | 字段冻结 |

### 3. 是否与目标价值一致

(取自 [docs/business/产品定位.md](../business/产品定位.md) §价值主张)

| 价值主张 | 主链路兑现方式 |
|---------|---------------|
| **决策效率**:1 小时 → 1.5 分钟 | 主流程端到端 ≤ 30 秒 + 输入 + 阅读 ≈ 1.5 分钟 |
| **跨平台视野**:同步看抖音 / 小红书 / 快手 | 三平台并行采样(见 [docs/business/选题漏斗.md](../business/选题漏斗.md) §第 2 层) |
| **按 TA 自己规模衡量**:小账号也能爆 | "小账号爆款"判定(见 [DOMAIN_RULES.md](DOMAIN_RULES.md) §3.3);相对自身评估的 conclusion |

### 4. 上线前必须的 5 个数(同步 [PRD-v1.md](../PRD-v1.md) §6)

1. 进站可用率 ≥ 95%
2. 预测时长 P95 ≤ 30 秒
3. 选题点击转化 ≥ 30%(预测会点击至少一张选题卡进入下一步)
4. 预测命中率 ≥ 40%(48h 后赛道点赞中位数提升 ≥ 30% 的样本占比)
5. NPS(20 人小样本) ≥ 30

> 任意一个不达标,v1.0 不上线。

## 失败路径与兜底

### 1. 用户失败路径

| 用户行为 | 现状 | 兜底 |
|---------|------|----|
| **输入空 / 全空格** | 不应触发 LLM | 前端按钮禁用 / 后端 `parseInput` 兜底返回 null |
| **输入过长**(超出业务上限) | `payload-extractor.merged` 用 maxTokens=1024 兜底,prompt 内截断 | 截断后提交,不报错 |
| **链接但拿不到内容**(限制登录 / 反爬) | `smart-link-parser.restriction` LLM 检测到 → 走"无内容"分支 | 主流程仍能跑(失去链接信号但走关键词路径) |
| **用户输入与赛道严重冲突** | `validateSearchKeywords` 校验后给提示;`trustExtractor=true` 时跳过 | 默认信任 extractor;不强制校正 |
| **用户长时间不操作 / 关闭浏览器** | SSE 长连接被前端断;后端继续算完落库 | 用户**重新打开**时能拿到历史预测结果(MySQL 持久化) |
| **未登录访问** | `protectedProcedure` 抛 `UNAUTHORIZED` | 前端跳到登录页 |
| **新用户积分不足** | 注册即送 60 积分(够 1–2 次完整预测);**v1.0 公开流只提示积分不足,不进入公开购买闭环** | 会员 / 积分入口保持隐藏,待 v1.1 再开放 |

### 2. 系统失败路径(主流程)

(详见 [docs/SLA-降级表.md](../SLA-降级表.md);摘录与用户感知最相关的几条)

| 失败 | 系统行为 | 用户感知 |
|------|--------|--------|
| TikHub 余额不足(`httpStatus=402`) | **阻断**:抛"TikHub 余额不足"+ 10 分钟全局冷却 | 看到友好错误提示;10 分钟内重试也会被冷却 |
| 单平台搜索失败(抖音 / 小红书 / 快手任一) | **降级**,merge 其他平台 | 候选样本变少,但仍能给结果 |
| 三平台全部失败 | **降级到热榜信号模式** | 结果质量下降但能给出 |
| `parseInput` 多模态超时(6s) | 返回 `null` | 链接 / 视频内容信号丢失,但仍可预测(走关键词路径) |
| `llmExtractAndClassify` 超时(12s) | 各自走兜底:`extractTaskParams` 内部 LLM + `classifyIntentWithLLM` | 慢但仍可成功 |
| 语义过滤主阈(≥7)后剩 < 3 条 | 自动降阈到 6 重跑 | 凑数比空盘好(见 [docs/business/算法白皮书.md](../business/算法白皮书.md) §4.2) |
| 评论补采失败 | **跳过**,不阻断 | 选题质量略下降 |
| **趋势 + 选题合并 LLM 失败**(35s 超时) | `trendOpportunities` 和 `aiTopicSuggestions` 都为空数组 | 趋势卡片和选题建议都消失,但其他模块仍展示;状态标 `degraded` |
| 文案生成失败(60s 默认超时) | 返回基础结果(无文案) | 用户看到选题但没有现成文案 |
| 整体 HTTP 超时 | Express `requestTimeout = 600s` 兜底 | 极少触发;若触发则前端断流后用户重试 |

### 3. AI 失败路径

| AI 行为 | 现状 | 兜底 |
|--------|------|----|
| Doubao 模型返回非合法 JSON | 业务层 `try/catch` 解析,失败时走该步降级路径 | 单步影响,主流程能继续 |
| Doubao 全停 / API key 失效 | 自动 fallback Forge | 输出风格 / 质量略变,但不阻断 |
| LLM 输出"凭空编对标"(referenceTitle 在样本池里查无) | **没有强校验**——目前依赖 prompt 要求 + evals 抽查发现 | ⚠️ 已知风险:见 [DOMAIN_RULES.md](DOMAIN_RULES.md) §6.1 反例 / [风险登记册.md](../business/风险登记册.md) §P0-#2 |
| LLM 输出 3 条选题角度雷同 | prompt 内要求多样性,无硬阻断 | ⚠️ 已知漏斗不足,见 [docs/business/选题漏斗.md](../business/选题漏斗.md) §已知不足 |
| AI 模型悄悄升级行为变化 | 🔴 **当前没有自动评测**——脚手架(`evals/topic-suggest/`)就位,接通待做 | 兜底:用户主动反馈 / 产品自测;计划:接通后周期跑评测对比基线 |

### 4. 人工兜底方式

> v1.0 阶段产品**不投入大量人工运营**,但下列场景需要人工:

| 场景 | 人工动作 | 频率 |
|------|--------|------|
| 任一周用户反馈"选题水了" > 3 次 | 立刻跑评测对比上一版基准(产品 + 算法) | 触发性 |
| 月度命中率 < 25%(打点上线后) | 启动算法 review | 月度触发 |
| 月度单次预测成本 > ¥3.5 | 立刻拆 LLM + 数据源,看是哪一段贵 | 月度触发 |
| TikHub 1 次 > 6 小时全停 | 立刻启动备用源调研(产品 + 技术) | 触发性 |
| 任一平台开测试"AI 选题"功能 | 立刻产品评估"我们的差异化在哪一段还成立"(创始人 + 产品) | 触发性 |
| 任意 P0 风险触发信号 | 召开应对会议(详见 [docs/business/风险登记册.md](../business/风险登记册.md)) | 触发性 |

人工 review 节奏(取自 [docs/business/风险登记册.md](../business/风险登记册.md) §风险评审节奏):
- **每周**(产品自审):P0 / P1 状态进度
- **每月**(团队 review):整张风险表过一遍
- **每季度**(战略层):重评等级

## 已知 UX 缺口(不影响 v1.0 必须达成,记录待 v1.1)

| 缺口 | 影响 | v1.1 计划 |
|------|------|----------|
| 选题卡下没有"相关 / 不相关"反馈按钮 | 用户隐性反馈无法采集 | 加单选反馈 + 后端打点(P2,见 [docs/business/指标体系.md](../business/指标体系.md) §当前打点缺口) |
| 没有"再来一次 / 微调关键词"快速重跑入口 | 用户不满意时只能整页重提交 | v1.1 评估 |
| 没有"历史预测"列表 | 用户无法回看之前的 3 张卡 | 后端有数据,前端列表页待补 |
| 移动端体验未优化 | v1.0 桌面优先,移动只保证不崩 | v1.1 backlog |
| 输入示例 / 引导不足 | 新用户不清楚"赛道关键词"怎么填 | 前端文案优化(冻结期内允许加固) |
