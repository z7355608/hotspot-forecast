# 爆款预测agent · 一页纸 PRD v1.0

> **文档定位**：v1.0 锁定文档。在 v1.0 上线前，任何与本文档冲突的需求一律延后或拒绝。
> **维护者**：项目 PM（单点拍板）
> **冻结日期**：2026-04-28
> **解冻条件**：M1–M5 全部达成 → v1.1 重新评估

---

## 1. 一句话产品承诺

> **输入一个赛道关键词、一条对标视频链接，或一个账号链接 —— 30 秒内，给出 3 个今天就能开拍的爆款选题，每个选题都附带具体对标样本和爆发指数。**

这一句话是衡量"做不做"的唯一标尺。任何不在这句话里的能力，v1.0 都不做。

---

## 2. 目标用户（v1.0 唯一聚焦）

**抖音 / 小红书的中腰部自媒体创作者**（粉丝 1k–50k）。
他们的痛点不是"不会拍"，而是"不知道现在该拍什么"。

**明确不服务**：
- MCN 投放运营 —— 他们要的是规模化数据看板，不是单选题
- 知识博主写长文 —— 爆款逻辑不一样
- 品牌投放方 —— 他们要的是种草数据

---

## 3. 核心闭环（用户必走的 3 步）

1. **输入**：赛道关键词 / 对标视频链接 / 账号链接（不超过 1 个输入框、不超过 1 次点击）
2. **预测**：30 秒内返回 3 张选题卡片（轮播）
3. **执行**：选定选题后，一键生成开拍脚本 / 一键拆解对标样本

> **所有不在这 3 步上的功能，在 v1.0 阶段全部隐藏或下线。**

---

## 4. v1.0 必须做的（Must）

| # | 项 | 验收标准 |
|---|---|---|
| **M1** | 服务端到端可用 | manus.space 域名下，新用户从打开到拿到结果页 < 60 秒，无 502 / 不刷新 / 不卡登录 |
| **M2** | 3 张选题卡片 | 每次预测稳定输出 ≥3 张选题，含：标题 / 切入角度 / 爆发指数 / 对标样本 / 核心标签 |
| **M3** | 数据相关性 ≥ 80% | LLM 语义过滤后，按默认验收草案抽样 50 条选题卡，相关率 ≥ 80%（见下） |
| **M4** | 一键生成脚本 | 点击"生成开拍脚本"必须跳到脚本编辑器并预填该选题上下文（标题/角度/对标/标签） |
| **M5** | 命中率可观测 | 默认复用内部受保护查询 / 后台页，能查看"预测分 vs 48 小时后真实表现"的最近样本与命中率 |

**M3/M5 默认验收草案**（除非 PM 明确推翻，否则按此执行）：
- M3 样本池 = 最近 7 天 `completed` / `degraded` 的真实预测结果；抽样单元 = 单条选题卡；同一次预测默认最多抽 1 条，直到凑满 50 条。
- M3 「相关」= 与用户输入赛道 / 任务直接相关，且属于"今天就能拍"的具体选题；泛泛同领域、错赛道、不可执行，均记为不相关。
- M3 评审方式 = PM + 1 名协作者独立打标；有分歧时以 PM 最终裁决为准。
- M5 默认不要求新做用户前台页面；内部受保护页面、后台页或查询脚本，只要能查看 `publishedTitle / predictedScore / actualScore / accuracy / latestPerformance` 与 48h checkpoint 记录，即视为"可观测"。

## 5. v1.0 不做的（Won't）—— 写下来防自己反悔

- ❌ 充值 / 会员 / 积分体系（subscriptions、credit_transactions、llm_usage_logs 全部隐藏入口）
- ❌ 内容日历（content_calendar 路由 404）
- ❌ 周度选题订阅（weekly_topic_subscription 路由 404）
- ❌ 首页"赛道情报""价值轮播""DashboardInsights"等装饰性模块
- ❌ 自定义赛道（已删除，不再加回）
- ❌ 多平台前端对比（v1.0 只暴露抖音；小红书等作为隐性数据源）
- ❌ 移动端适配（v1.0 桌面优先，移动端只保证不崩）
- ❌ 结果页 UI / 选题卡片 / AI 文案的任何新一轮"视觉编辑反馈"

---

## 6. 成功指标（4 周后看这 5 个数）

1. **进站可用率**：新用户从落地到看到结果页的成功率 ≥ 95%
2. **预测时长 P95**：30 秒以内
3. **选题点击转化**：≥ 30% 的预测会点击至少一张选题卡进入下一步
4. **预测命中率**：48 小时后，选题相关赛道点赞中位数提升 ≥ 30% 的样本占比 ≥ 40%
5. **NPS（小样本 20 人）**：≥ 30

> 这 5 个数任意一个不达标，v1.0 不上线。

---

## 7. 决策机制（防止再被反馈推着走）

**冻结期规则**：v1.0 完成 M1–M5 之前，结果页 UI / 选题卡片 / AI 文案不再迭代。

**任何新需求**先回答 3 个问题：
1. 是否影响 M1–M5 的达成？
2. 是否动到了第 5 节的 ❌ 清单？
3. 用户能不能等到 v1.1？

→ 三个回答中任意一个为"否"，则进 backlog，不进当前 sprint。

**PM 单点拍板权**：所有 UI / 文案 / 字段的变更必须经 PM 一句话同意。
不再做"用户视觉编辑反馈 v4 / v5 / v6"。

## 8. 与现有代码资产的关系

**保留并稳定**（这些是 v1.0 的核心资产）：
- `server/legacy/live-predictions.ts`（预测主链路）
- `server/legacy/semantic-filter.ts`（LLM 语义过滤）
- AI 选题生成（含 conclusion / howToShoot / whyNow / tags / score 字段，**字段冻结**）
- 结果页选题卡片轮播（**UI 冻结**）
- TikHub 搜索 / 低粉爆款榜 / 热搜榜接入
- **低粉爆款样本库 = 双管线**(管线 A 用户 seed_topic 检索 + 管线 B 抖音 billboard 按行业拉,见 [ADR-0007](decisions/0007-low-follower-billboard-pipeline.md))。`low_follower_samples.source` 字段标识来源,合格样本定义按 [ADR-0006](decisions/0006-low-follower-library-target-alignment.md)。

**保留但隐藏入口**（不删代码，避免回滚负担）：
- 充值、会员、积分相关页面与 API
- 内容日历、周度订阅
- 首页 DashboardInsights / ValueCarousel

**v1.0 不再扩展的部分**：
- 任何新字段加到 `AiTopicSuggestion`
- 任何新折叠区加到结果页
- 任何新 LLM 调用加到主链路
