# 业务文档

> 产品定位、采集策略、算法、流程、指标——**用大白话**写的项目说明,
> 给产品负责人、运营、合作方、新成员上手。
>
> 所有规则、阈值、字段、时间窗,都从代码里摸出真实值,
> 每条事实后面附上文件位置,**文档与代码同源**,改代码就改文档。

---

## 写作标准

每一项产品决策都按 **5 个角度**说清楚:

| 决策点 | 规则 | 时间维度 | 评测维度 | 过滤标准 | 为什么这样选 | 备选 + 否决理由 |
|--------|------|---------|---------|---------|-----------|------------|

前 4 列是**事实**(任何人摸代码都能拿到),"为什么"和"备选"才是产品判断力的体现。
没有"为什么"的决策不算决策——只是惯性。

---

## 写作语言:坚持大白话

**业务文档不出现"技术黑话"**——读者不需要知道这些专业术语是什么。
团队成员写业务文档时,统一按下表翻译:

| 技术词 | 大白话 |
|--------|------|
| TikHub | 数据源(抓取抖音/小红书/快手内容的服务商) |
| TikHub endpoint | 数据接口 |
| LLM / 大模型 | AI / AI 大模型 |
| LLM 调用 / 调一次 LLM | 调一次 AI |
| prompt | AI 题目 / AI 输入指令 |
| API / endpoint | 接口 / 外部服务 |
| token / maxTokens | AI 一次回答的字数(消耗) |
| temperature | AI 的发散程度(高=灵活, 低=保守) |
| P75 / 75 分位 | 同赛道前 25%(只有四分之一比它高) |
| P95 时延 | 95% 用户能在这个时间内拿到结果(常态最慢值) |
| TTL / cache TTL | 缓存有效期 |
| LRU 缓存 | 内存里只留最近用的 |
| cron / `*/10 * * * *` | 定时任务 / 每 10 分钟跑一次 |
| SaaS | 在线工具(月费产品) |
| evals / 自动评测 | AI 输出回归测试(改完看会不会更差) |
| baseline | 上一版的成绩 |
| A/B 测试 | 把用户分两组对比 |
| ADR | 决策记录 |
| Aha moment | 用户第一次"觉得真有用"的时刻 |
| DAU / WAU / MAU | 日活 / 周活 / 月活 |
| ARPU | 每月每用户收入 |
| LTV | 用户终身付费总额 |
| CAC | 招一个新用户花多少钱 |
| LTV/CAC | 招一个用户能赚回几倍 |
| NPS | 用户推荐意愿分 |
| guardrail | AI 输出限制(防止说不该说的) |
| fallback | 备用方案 |
| timeout | 超时(等多久没回应就当挂了) |
| retry | 失败后重试 |
| concurrency | 同时跑几个 |
| rate limit | 限速 |
| 7 维评分(opportunity / risk / 等) | 7 维打分(机会分 / 风险分 / 等) |
| LLM-as-judge | 让另一个 AI 来评分 |

**例外**:LTV / CAC / DAU 这种**通用商业术语**,在跟懂行的人(投资人、合作方)讨论时
可以保留——但**第一次出现时仍要带括号解释**。

## 维护原则

- **代码改了,文档同步改**——不一致就是失效
- **价格 / 阈值 / 容量 / 时长 必须从代码引用,严禁凭直觉编占位数**
  - 真值出处:`server/routers/credits.ts`(套餐价 + 积分包)、`server/legacy/llm-gateway.ts`
    (模型价)、`server/legacy/database/seed-skills.mjs`(prompt 模板)等
  - 一次踩坑示例(2026-04-29):产品定位写过 "¥99/月"占位价,真实是 Plus ¥19 / Pro ¥49,
    差 4–6 倍——单位经济模型也跟着错了一倍
- 每个决策的"为什么"想不出 3 条理由 → 这个决策本身就要重新审视
- 阈值是经验值的,**注明**(不要假装有数据支撑)
- 真实打点缺的指标,在文档里标 🔴/🟡——不要含糊带过
- 写完看一遍:这一句**读者会问"X 是什么意思"吗?**——如果会,就是没说人话
