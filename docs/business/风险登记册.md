# 风险登记册

> 团队对外部 / 内部已知风险的统一记录。每条给出
> **触发条件 / 业务影响 / 应对预案 / 当前进度**。
>
> 优先级 = 概率 × 影响。**P0 必须有应对**;P1 必须有"什么时候开始处理"的判断;
> P2 列出来即可,撞上再说。

---

## TL;DR(1 屏速览)

**3 个 P0 风险**(必须有应对):

1. 🔴 **数据源(单一供应商)挂掉** —— 全产品停摆,**当前无备用源**
2. 🔴 **AI 模型行为悄悄变化** —— 选题质量下滑而看不见,**自动评测没接通**
3. 🔴 **平台自己下场做** —— 单平台用户流失 50%+,跨平台 + 小创作者定位是护城河

**4 个 P1 风险**(规划应对):

4. 🟠 命中率不达标 —— 数据原料有,**指标聚合未上**
5. 🟠 单次预测成本失控 —— LLM 预算约束已立,**真实成本未打点**
6. 🟠 竞品价格战 —— 等首批用户口碑站住
7. 🟠 多服务器数据漂移 —— 当前单服务器,1,000 日活前不动

**3 个 P2**(列着撞上再说):内容/合规、核心成员离职、数据源涨价

> **下一步最该做的 2 件事:**
> ① 接通自动评测(化解 #2);② 打点单次成本和命中率(化解 #4 和 #5)

## P0:数据源挂掉或停服

| 维度 | 内容 |
|------|------|
| **触发条件** | 数据接口供应商(TikHub)全平台不可用 / 公司倒闭 / 价格大涨 / 合规问题 |
| **业务影响** | 主预测流程**全停**——产品没数据可分析。每停 1 天 ≈ 当日营收 100% 损失 + 用户口碑重创 |
| **当前应对** | 技术层:供应商返回"余额不足"时进 10 分钟冷却 → 用户看到友好提示<br>商业层:**无任何备用源**——这是真实的单点风险 |
| **建议预案** | ① 评估第二数据源(自建有限范围爬虫 / 其他供应商)<br>② 跟现供应商谈服务等级协议(目前是普通付费用户)<br>③ 数据缓存加持久化,挂掉时至少能展示历史数据降级 |
| **触发应对的信号** | 供应商出现 1 次 > 6 小时全停 → 立刻启动备用源调研 |
| **负责人** | 产品 + 技术联合 |

## P0:AI 大模型行为悄悄变化

| 维度 | 内容 |
|------|------|
| **触发条件** | 火山方舟悄悄升级豆包模型版本,选题输出风格 / 准确性变化 |
| **业务影响** | 主流程的两次关键 AI 调用("找趋势"和"出选题")输出"看起来差不多但用户感知变烂"——**最阴险的风险**:核心指标缓慢下滑而我们看不见 |
| **当前应对** | 🔴 **没有自动评测**——完全依赖用户主动反馈或产品自测发现 |
| **建议预案** | ① 接通自动评测(代码已搭好脚手架,见 evals/ 目录),周期跑(每天/每周)<br>② 设定基准成绩,跌出阈值告警<br>③ 备用 AI 大模型(GPT / Claude)随时可切换(代码已支持,见决策记录 0001) |
| **触发应对的信号** | 任意周用户反馈"选题水了" > 3 次 → 立刻跑评测对比上一版基准 |
| **负责人** | 算法 / 产品 |

## P0:平台直接做同类功能

| 维度 | 内容 |
|------|------|
| **触发条件** | 抖音 / 小红书在创作者中心加"AI 选题推荐"功能 |
| **业务影响** | 单平台用户可能流失 50%+——**不是末日,但损失重**:腰部以下创作者会优先用平台原生工具(免费、入口深) |
| **概率分析** | 平台做单平台 AI 选题 = 大概率会做(2 年内);**做跨平台** = 几乎不可能(违反平台利益) |
| **当前应对** | **跨平台**是核心护城河——产品强调"看竞品平台风向" |
| **建议预案** | ① 扩到更多平台(B 站、视频号)拉宽护城河<br>② 加深"个性化 + 按用户自身水平评估"——平台原生工具不会针对个体相对评估<br>③ 评估**被收购**作为退出选项——在线工具行业惯例 |
| **触发应对的信号** | 任一平台开测试"AI 选题"功能 → 立刻产品评估"我们的差异化在哪一段还成立" |
| **负责人** | 创始人 + 产品 |

## P1:命中率不达标(效果风险)

| 维度 | 内容 |
|------|------|
| **触发条件** | 用户拍了 AI 推的选题之后,达爆款门槛的比例 < 行业自然值(~5–8%) |
| **业务影响** | 用户口碑跌 → 续费率跌 → 用户终身付费缩水 → 单位经济模型崩 |
| **当前应对** | 🟡 数据原料有(每 4 小时回访一次拍后表现),**指标没聚合,看不见**——见 [指标体系.md](指标体系.md) |
| **建议预案** | ① 优先级 P0:把命中率指标先打点出来<br>② 建立"命中率周报"看板<br>③ 命中率连续 4 周下滑 → 触发算法回溯(看 AI 题目改没、模型升没、数据源变化) |
| **触发应对的信号** | 命中率打点跑起来后,任何月度低于 25% → 启动算法 review |
| **负责人** | 产品 + 算法 |

## P1:成本失控

| 维度 | 内容 |
|------|------|
| **触发条件** | AI 大模型涨价 / 数据缓存命中低 / 后台定时任务失控 |
| **业务影响** | 单次预测成本翻倍 → 招一个用户能赚回的倍数从 6.3 跌到 < 3 → 不能投钱拉新用户 |
| **当前应对** | 已有"AI 调用预算"约束文档,但**真实成本没打点**(预算约束只是纸面) |
| **建议预案** | ① 在 AI 调用入口加字数 + 成本打点(P0,1 周工作量)<br>② 单次预测成本月度看板,异常告警<br>③ 缓存命中率打点,低于 X% 启动优化(给 AI 题目加缓存) |
| **触发应对的信号** | 月度单次预测成本 > ¥3.5 → 立刻看是哪一段贵 |
| **负责人** | 产品 + 技术 |

## P1:竞品价格战

| 维度 | 内容 |
|------|------|
| **触发条件** | 飞瓜 / 千瓜 / 卡思 等老牌数据工具下沉到 ¥99 / 月级别,直接对标我们 |
| **业务影响** | 招客成本飙——这些公司有现成销售渠道和品牌信任<br>但有信号:他们的产品形态是"数据看板",**不是 AI 决策**,转身慢 |
| **当前应对** | 暂无主动应对——v1.0 阶段先把第一批种子用户口碑站住 |
| **建议预案** | ① 维持差异化(AI 决策 + 跨平台,不要变成"小一号的飞瓜")<br>② 增长靠创作者社群口碑,**避开广告战**(打不过)<br>③ Pro 年付(¥300/年)做 MCN 渠道——价格仅竞品 1/10,绝对优势 |
| **触发应对的信号** | 任意主流数据工具上线低于 ¥150 / 月套餐 → 产品评估对位策略 |
| **负责人** | 产品 + 增长 |

## P1:多服务器部署时数据漂移

| 维度 | 内容 |
|------|------|
| **触发条件** | 用户量增长后,单服务器承不住,需要多服务器部署 |
| **业务影响** | 当前账号绑定、缓存、定时任务都是**单服务器本地状态**,多服务器会数据漂移、用户绑定丢失、定时任务重复跑——严重时**用户体验崩盘** |
| **当前应对** | 当前**单服务器**部署,问题暂未暴露<br>详见 [部署文档](../deployment.md) "多实例瓶颈" 段 |
| **建议预案** | ① 用户量到 1,000 日活之前继续单服务器(成本最低)<br>② 1,000 日活之后,把本地状态全部迁到数据库,加共享缓存层,定时任务单服务器化(2 周工作量) |
| **触发应对的信号** | 单服务器 CPU/内存常态使用率 > 70% → 启动多服务器工作 |
| **负责人** | 技术 |

## P2:内容/合规风险(轻量记录)

| 维度 | 内容 |
|------|------|
| **触发条件** | AI 输出生成了"医疗建议 / 投资承诺 / 政治敏感 / 违规内容"被用户截图传播 |
| **业务影响** | 平台投诉、媒体反弹、最坏情况监管问询 |
| **当前应对** | 代码层暂无 AI 输出限制 / 敏感词过滤 / 用户授权层——已识别为缺口 |
| **建议预案**(撞墙前不主动做) | ① 给 AI 题目加输出限制(快,几小时)<br>② AI 输出后接敏感词过滤(中,1 周)<br>③ 用户协议加内容免责 + 隐私声明(产品/法务,1–2 周) |
| **为什么是 P2 而不是 P0** | 用户群体是腰部创作者,选题方向偏生活/创意类,落入敏感区域概率低;真撞上再补来得及 |
| **负责人** | 产品(撞上时立刻联合法务) |

## P2:数据源价格上调

| 维度 | 内容 |
|------|------|
| **触发条件** | 数据源单价从 $0.01 涨到 $0.02+ |
| **业务影响** | 单次预测成本约 +0.7 元 → 月毛利略缩 |

## 风险评审节奏

| 频率 | 内容 |
|------|------|
| **每周**(产品自审) | P0 / P1 状态 → 进度有没有更新?触发信号有没有出现? |
| **每月**(团队 review) | 整张表过一遍,新增风险加进来,已闭环的标 done |
| **每季度**(战略层) | 重新评估等级——曾经的 P0 是否已经降级,曾经的 P2 是否上升 |
| **触发性**(撞上时) | 任意 P0 / P1 触发信号出现,**立刻**召开应对会议 |
